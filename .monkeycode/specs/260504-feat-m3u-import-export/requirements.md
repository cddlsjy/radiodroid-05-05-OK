# M3U文件导入导出功能需求文档

## 文档信息
- **需求ID**: 260504-feat-m3u-import-export
- **创建日期**: 2026-05-04
- **状态**: 待实施

## 1. 需求概述

### 1.1 需求描述
为RadioDroid应用增加M3U文件导入导出功能,允许用户通过M3U格式的播放列表文件批量导入和导出电台列表。

### 1.2 背景
当前应用已有收藏和历史记录功能,但缺乏便捷的批量导入导出能力。M3U是广泛使用的播放列表格式,支持电台名称、流地址和图标信息的存储。通过引入M3U导入导出功能,用户可以:
- 备份自己的电台列表
- 在不同设备间同步电台收藏
- 分享电台列表给其他用户
- 从其他播放器导入已有的电台列表

### 1.3 M3U格式说明
根据需求提供的示例,M3U文件格式如下:

```
#EXTM3U
#EXTINF:-1,AsiaFM亚洲经典台
#EXTIMG:http://pic.qtfm.cn/2022/0712/20220712122112.jpeg!200
http://goldfm.cn:8000/goldfm

#EXTINF:-1,AsiaFM高清音乐台
http://asiafm.hk:8000/asiahd
```

## 2. 功能需求

### 2.1 导入功能 (FR-001)
**需求描述**: 系统应当允许用户从本地文件系统选择并导入M3U格式的电台列表文件。

**详细要求**:
- **FR-001.1**: 提供导入M3U文件的菜单入口,支持从收藏和历史记录标签页触发
- **FR-001.2**: 使用文件选择器让用户选择M3U文件
- **FR-001.3**: 解析M3U文件内容,提取电台信息(名称、流地址、图标)
- **FR-001.4**: 支持标准M3U格式,包括:
  - `#EXTM3U` - M3U文件头标识
  - `#EXTINF:-1,电台名称` - 电台名称信息
  - `#EXTIMG:图标URL` - 电台图标URL(可选)
  - 流地址URL - 必须以http://或https://开头
- **FR-001.5**: 导入过程中显示加载提示,并在完成后显示导入结果
- **FR-001.6**: 如果导入的电台在收藏列表中已存在,不重复添加
- **FR-001.7**: 导入的电台应支持播放、删除等常规操作

**验收标准**:
- 用户可以成功导入包含多个电台的M3U文件
- 导入后电台列表正确显示,名称和流地址正确
- 支持带图标URL的M3U文件导入
- 导入过程有明确的用户反馈

### 2.2 导出功能 (FR-002)
**需求描述**: 系统应当允许用户将当前的电台列表导出为M3U格式的文件。

**详细要求**:
- **FR-002.1**: 提供导出M3U文件的菜单入口,支持从收藏和历史记录标签页触发
- **FR-002.2**: 使用文件选择器让用户指定保存位置和文件名
- **FR-002.3**: 生成的M3U文件应包含所有电台的完整信息:
  - 文件头: `#EXTM3U`
  - 每个电台的`#EXTINF:-1,电台名称`行
  - 如果电台有图标,添加`#EXTIMG:图标URL`行
  - 流地址URL行
- **FR-002.4**: 默认文件名格式: `RadioDroid_YYYYMMDD_HHMMSS.m3u`
- **FR-002.5**: 导出过程中显示进度提示,并在完成后显示保存位置
- **FR-002.6**: 导出完成后,如果设备支持,通知媒体库扫描器更新

**验收标准**:
- 用户可以成功导出当前电台列表为M3U文件
- 导出的M3U文件格式正确,可以被其他播放器识别
- 导出的电台信息完整,包括名称、流地址和图标(如果有)
- 导出过程有明确的用户反馈

### 2.3 新增"自定义"标签页 (FR-003)
**需求描述**: 在"热门"标签页之前,新增一个"自定义"标签页,用于显示用户导入的电台列表。

**详细要求**:
- **FR-003.1**: 在导航菜单中,在"热门"标签页之前插入"自定义"标签页
- **FR-003.2**: "自定义"标签页专门用于显示用户通过M3U文件导入的电台
- **FR-003.3**: "自定义"标签页中的电台支持:
  - 播放电台
  - 添加到收藏
  - 删除电台
  - 查看电台详情
- **FR-003.4**: "自定义"标签页中的电台删除后,从列表中移除
- **FR-003.5**: "自定义"标签页支持搜索功能
- **FR-003.6**: "自定义"标签页的数据持久化存储

**验收标准**:
- "自定义"标签页正确显示在导航菜单中
- 导入的M3U电台正确显示在"自定义"标签页中
- "自定义"标签页中的电台可以正常播放和管理
- 应用重启后,"自定义"标签页的数据能够正确恢复

### 2.4 数据管理 (FR-004)
**需求描述**: 系统应当提供自定义电台列表的数据管理功能。

**详细要求**:
- **FR-004.1**: 自定义电台列表与收藏列表、历史记录列表独立存储
- **FR-004.2**: 自定义电台列表支持添加、删除、清空操作
- **FR-004.3**: 自定义电台列表支持批量导入(M3U文件导入)
- **FR-004.4**: 自定义电台列表支持导出为M3U文件
- **FR-004.5**: 自定义电台列表的数据使用SharedPreferences持久化存储

**验收标准**:
- 自定义电台列表的数据能够正确保存和加载
- 数据操作(添加、删除、清空)能够正确持久化
- 不同列表之间的数据互不影响

## 3. 非功能需求

### 3.1 性能需求 (NFR-001)
- **NFR-001.1**: M3U文件导入应在1秒内完成(针对100个电台的文件)
- **NFR-001.2**: M3U文件导出应在1秒内完成(针对100个电台的列表)
- **NFR-001.3**: 自定义标签页的列表加载应在500ms内完成(针对100个电台)

### 3.2 易用性需求 (NFR-002)
- **NFR-002.1**: 导入导出操作应提供清晰的进度提示
- **NFR-002.2**: 操作失败时应显示友好的错误提示信息
- **NFR-002.3**: 导入导出的成功/失败结果应使用Toast消息明确告知用户

### 3.3 兼容性需求 (NFR-003)
- **NFR-003.1**: 支持标准M3U格式,与常见播放器(如VLC、Winamp等)兼容
- **NFR-003.2**: 支持扩展M3U格式,包含电台名称和图标信息
- **NFR-003.3**: 支持UTF-8编码的M3U文件,正确处理中文电台名称

### 3.4 可靠性需求 (NFR-004)
- **NFR-004.1**: 导入格式错误的M3U文件时,应跳过错误行,继续处理有效数据
- **NFR-004.2**: 导入过程中发生异常时,不应导致应用崩溃
- **NFR-004.3**: 导出过程中发生异常时,应提示用户并取消操作

### 3.5 安全性需求 (NFR-005)
- **NFR-005.1**: 导入M3U文件时,验证URL格式的合法性
- **NFR-005.2**: 不执行M3U文件中的任何代码,仅作为数据解析
- **NFR-005.3**: 导出的M3U文件仅包含电台数据,不包含敏感信息

### 4.1 导航菜单 (UI-001)
**需求描述**: 在导航菜单中新增"自定义"标签页入口。

**详细要求**:
- **UI-001.1**: "自定义"标签页位于"热门"标签页之前
- **UI-001.2**: 使用合适的图标标识"自定义"标签页
- **UI-001.3**: 标签页名称为"自定义"

### 4.2 导入导出入口 (UI-002)
**需求描述**: 在收藏和历史记录标签页的工具栏中添加导入导出入口。

**详细要求**:
- **UI-002.1**: 在收藏标签页的工具栏添加"导入"和"导出"按钮
- **UI-002.2**: 在历史记录标签页的工具栏添加"导入"和"导出"按钮
- **UI-002.3**: 在自定义标签页的工具栏添加"导入"和"导出"按钮
- **UI-002.4**: 导入导出按钮使用合适的图标

### 4.3 文件选择器 (UI-003)
**需求描述**: 使用系统的文件选择器进行M3U文件的选择和保存。

**详细要求**:
- **UI-003.1**: 导入时,文件选择器默认过滤显示.m3u和.m3u8文件
- **UI-003.2**: 导出时,文件选择器提供默认文件名`RadioDroid_YYYYMMDD_HHMMSS.m3u`
- **UI-003.3**: 文件选择器支持用户浏览文件系统

## 5. 数据需求

### 5.1 数据存储 (DS-001)
**需求描述**: 自定义电台列表的数据需要持久化存储。

**详细要求**:
- **DS-001.1**: 使用SharedPreferences存储自定义电台列表
- **DS-001.2**: 存储键名: `custom_stations`
- **DS-001.3**: 存储格式: JSON数组,包含电台的完整信息
- **DS-001.4**: 每个电台包含: StationUuid, Name, StreamUrl, IconUrl, HomePageUrl等字段

### 5.2 数据格式 (DS-002)
**需求描述**: M3U文件的格式规范。

**详细要求**:
- **DS-002.1**: 文件头: `#EXTM3U`
- **DS-002.2**: 电台信息行: `#EXTINF:-1,电台名称`
- **DS-002.3**: 电台图标行(可选): `#EXTIMG:图标URL`
- **DS-002.4**: 流地址行: `http://`或`https://`开头的URL
- **DS-002.5**: 电台条目之间使用空行分隔
- **DS-002.6**: 支持UTF-8编码

## 6. 约束条件

### 6.1 技术约束
- 基于现有的RadioDroid代码库,使用Java开发
- 使用现有的StationSaveManager框架
- 使用现有的文件对话框库(com.rustamg.filedialogs)
- 最小支持Android API 19 (Android 4.4 KitKat)

### 6.2 业务约束
- 导入的电台不自动同步到服务器
- 自定义电台列表与收藏列表独立管理
- 删除自定义电台不影响收藏列表和历史记录

### 6.3 用户体验约束
- 导入导出操作应在后台线程执行,不阻塞UI
- 提供清晰的用户反馈,包括进度提示和结果通知
- 错误信息应友好且易于理解

## 7. 依赖关系

### 7.1 功能依赖
- 导入功能依赖于M3U文件解析器
- 导出功能依赖于M3U文件生成器
- 自定义标签页依赖于数据持久化存储
- 所有功能依赖于文件读写权限

### 7.2 外部依赖
- Android文件系统访问权限
- 媒体库扫描器(MediaScannerConnection)
- Gson库(JSON序列化)
- OkHttp库(网络请求,用于获取远程电台信息)
